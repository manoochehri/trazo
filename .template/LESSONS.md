# Lessons learned

Each lesson: what happened, what it cost, and how the template now prevents it.
Add new lessons here when working **in Trazo**. A mounted project's own lessons belong in that project.

| # | Lesson | Source | Template change |
|---|---|---|---|
| 1 | Agents lose context on reset; a handoff kept only in chat had to be rebuilt from memory. | project 1 | State lives in `docs/`; `/start` and `/wrapup`; decision 0001 |
| 2 | One growing project log becomes unreadable and mixes status with history. | project 1 | Split into CHARTER / STATUS / decisions / workstreams / reports |
| 3 | A result scored against the system's own model looked positive when the real result, measured against the market, was negative. | project 1 | CLAUDE.md rule 4; PR checkbox; advisor checks evidence quality |
| 4 | An agent quietly loosened a safety threshold without approval. | project 1 | Safety paths in CODEOWNERS; rule 5; automation may only tighten |
| 5 | Notes claimed a library lacked a feature; nobody had checked its source, and it existed. | project 1 | CLAUDE.md rule 3: verify, mark unverified |
| 6 | Copy-pasting between advisor chat and coding agent lost information and time. | project 1 | ADVISOR.md; outcomes written to the repo; agents read the repo directly |
| 7 | Cloud access tied to a human login session (12h expiry) broke automation. | project 1 | OIDC deploy role; deploys gated by one-click environment approval |
| 8 | Nightly jobs scheduled before their timers were installed silently missed their first run. | project 1 | (not yet) add "first run verified" to deploy checklist |
| 9 | Data volume grew 5x after adding sources; 30-day retention would overflow the disk. | project 1 | (not yet) runbook: disk-days-remaining in status |
| 10 | Cost estimates left out disks and public IPs, roughly doubling the real monthly cost. | project 1 | (not yet) kickoff: price every resource before deploy |
| 11 | Instructions written for a fresh agent needed a glossary and an explain-it-back step to be understood reliably. | project 1 | ADVISOR.md "for the coding agent"; `/start` explain-back |
| 12 | Security-heavy sessions (IAM, secrets, network probes) can trip safety filters; fresh sessions with repo-held state recover cleanly. | project 1 | Disposable sessions + repo memory |
| 13 | The first CI run failed on a job-level `hashFiles()` condition; local YAML checks didn't catch it because the file only becomes invalid once GitHub evaluates it. | project 1 | CI: job-level `hashFiles()` conditions moved into the step, after checkout |
| 14 | A long list of commands is hard to remember. | semilla | Plain-English routing in CLAUDE.md; `/semilla` menu |
| 15 | Requiring PR approvals on a solo repo blocks the owner (can't approve own PRs). | semilla | Kickoff ruleset requires PR + CI, not approvals, when solo |
| 16 | A template-wide find/replace of the owner placeholder rewrote the path `.github/CODEOWNERS` into `.github/CODE<user>S`, so the file matched no rule and could be edited without owner review. | semilla | Substitution anchored to the `{{OWNER}}` placeholder (never a bare `OWNER`); test asserts CODEOWNERS covers itself |
| 17 | "Is this in the agent's context?" was being answered from recollection. A fresh headless session with every file-reading tool denied settles it: if a marker token comes back with no `tool_use` block in the transcript, it was inlined, not read. A no-import control case guards the negative. | semilla | Technique recorded in `.trazo/project/workstreams/claude-md-imports.md`; issue #38 |
| 18 | A root `CLAUDE.md` `@import` silently fails to expand when the session starts in a subdirectory: the file loads, the `@` line survives as literal text, and the rules do not. Contradicts the docs, and fails open — an agent runs ungoverned with nothing reporting it. | semilla | Launch agents from the repo root; CI assertion that every `@` target resolves |
| 19 | The local secrets gate mounted only the working tree. Inside a git worktree `.git` is a *file* pointing at the shared git dir, outside that mount, so gitleaks resolved no repository, scanned 0 commits, printed "no leaks found" and exited 0 — a gate reading green in the exact place worktrees made the default. A verification gate that cannot tell what it scanned is worse than no gate, because it is trusted. | semilla | `make scan` mounts the shared git dir and runs an in-container preflight that exits non-zero, with the reason, whenever git cannot resolve commits (issue #43) |
| 20 | The handoff protocol forbade the *engineer* answering in chat but said nothing about the *PM* asking the owner to pass work on, or a decision arriving in chat never reaching the issue — each a different clause in a different file, so fixing only the one that got reported left the loop open. A rule about who may say what is only as strong as the sentences nobody thought to write. | semilla | `pm.md` forbids routing work through the owner and requires a defended ranking of every open issue; `work.md` records a decision on the issue before acting on it; 8 guards (issue #57) |
| 21 | A result that looks internally consistent and reproducible is exactly the kind that survives review, because the agent that built it reads the output as if it meant what it meant. A second question in the same conversation inherits those blind spots, so an adversarial reviewer has to be a separate read-only subagent, invoked every time rather than when something looks suspicious. | semilla | `skeptic` subagent + `.trazo/project/SKEPTIC_BAR.md` + standing rule 8 gating quantitative claims before a permanent record (issue #58) |
| 22 | A `Closes #N` in a pull request body is not a promise that the issue closes. On a squash merge only the commit message lands on the default branch, and GitHub resolves the close from *that* — so a body-only keyword links the issue without closing it. `closingIssuesReferences` is populated in that case, so it looks linked and works fine, which is why three PRs in a row merged "successfully" and left their issues open for the work queue to report as ready. | semilla | `work.md` step 4 puts the keyword in the commit message and names the squash reason; `/wrapup` step 5 verifies each merged PR's issue is actually CLOSED and closes it if not; the reviewer checks it (issue #61) |
| 23 | An issue drafted days earlier can name a decision number and a file count that another PR has since taken and changed. Writing it into an append-only record verbatim would have made a permanent document wrong in two ways at once — a record that is confidently false is worse than no record, because the next agent trusts it. Verify every number in a spec against the tree it will live in, and pin the commit so the claim stays checkable. | semilla | Decision 0005 records the pivot with counts measured on a pinned commit; `tests/test_decision_records.py` asserts numbering is unique and contiguous, statuses are valid, and 0005's numbers still hold (issue #49) |
| 24 | Moving a directory is not a `git mv` and a green build. Three things had to follow the move by hand, each of which fails silently: a test that pinned a decision record by path *and* by SHA-256 (the path breaks, the content does not), a CODEOWNERS rule that protected a file under its old name (a moved path that matches no rule protects nothing — #14 again), and a CI job that grepped changed files for the old path (the gate keeps reporting success while watching nothing). `git mv` also leaves empty directories behind that git never tracks, so a fresh clone and a working session disagree about whether the move finished. | semilla | `tests/test_trazo_layout.py` asserts no path points at a file that does not exist, the old paths are unreferenced, CODEOWNERS and the CI gate still cover the new paths, and the operational files stay in `docs/` (issue #50) |
| 25 | Deleting a placeholder package breaks four things, and three of them fail quietly: a `pyproject.toml` that still names the package makes `uv sync` fail inside hatchling with a traceback that reads like a broken environment; a Dockerfile `CMD` naming the removed module builds cleanly and fails only at run time, and CI only builds; `make run`/`make build` survive as no-ops so a derived project inherits commands that report success without doing anything. The tests are the thing that must keep passing, so the fix is configuration, never deleting a test to make the run go green. | semilla | `tests/test_no_app_placeholder.py` asserts the files are gone, nothing references the package, the targets are gone, the project is marked `package = false`, the Dockerfile has a runnable CMD, and the two #14 harness guards survive (issue #51) |
| 26 | A GitHub rename is an out-of-band change, so nothing in the repo notices. `.github/workflows/docs.yml` gated its artifact upload and its deploy on `github.repository == 'manoochehri/semilla'`; after the rename that condition can never be true, so every push to `main` would build the site, skip both steps, and report **green**. The docs site would stop updating while CI said everything passed. Only the live `curl` showed the old content was still being served — because the last successful deploy had happened before the rename. | semilla | `tests/test_repo_name.py` asserts no live file references the old slug, and specifically that the Pages deploy gate names the repository the workflow actually runs in; historical records (ADRs, CHANGELOG, LESSONS) are excluded on purpose because they describe what was true when written (issue #52) |
| 27 | Changing the *delivery* model invalidates the tooling built for the old one, and the leftovers do not announce themselves. Trazo pivoted from a starter template to a mountable overlay (#0005), which quietly made `/template-sync` meaningless (a mounted repo has no upstream) and `/template-improve` wrong (it wrote a PR to Trazo's own internals from inside someone else's project). What actually broke first were not the commands but the two things that *pointed* at them: `publish_template.sh` substituted into a file that no longer existed, and a CODEOWNERS guard sourced the owner's handle from that same file — a second copy of an identity in a place nobody edits, one deletion away from breaking. | semilla | `/template-sync`, `/template-improve` and the upstream pointer are gone; the owner's handle is read from CODEOWNERS itself; `test_publish_does_not_mention_the_removed_upstream_pointer` asserts against the script's loop rather than its text (issue #73) |
| 28 | A repo rename is mechanical; a user-facing rename is an API change. The menu command was `/semilla` in six live surfaces (a CLAUDE.md route table, the README, and the handbook's guide/team/playbook) while the repo underneath had already become trazo. Nothing broke visibly: the command simply stopped existing, and every doc mentioning it went on teaching a command that could not be typed. The distinction that made it tractable is that `owner/semilla` in a `--template` example is a derived project's suggested name, while `/semilla` is this project's command — anchoring the sweep on the leading slash separated them and left the historical records untouched without an exemption list per file. | semilla | `.claude/commands/semilla.md` -> `trazo.md`; `tests/test_trazo_command.py` asserts the command exists under one name only, keeps a discoverable description, and that no live file teaches the old name (issue #72) |
| 29 | A rename leaves the *published* site behind, because `handbook/` is `docs_dir` and nothing builds it against the repository name. The repo became trazo (#52), the delivery model became an overlay (#0005) and the flywheel commands were deleted (#73), while the site went on serving `<title>semilla</title>` and promising that each project "sends what it learned back" — a mechanism that no longer existed. Two of the three false claims were not nouns, so a find-and-replace could not have fixed them: they needed a rewritten thesis. And the mark was a seed/sprout, a pun on *semilla*, so the identity drifted too. A wordmark fixes that class for good, because it spells the name instead of illustrating it. | semilla | Home page rewritten around the overlay and the judgment layer; new `handbook/overlay.md` documents the layout and the mount-time contract; guide gains a mounting option; wordmark logo + favicon; `tests/test_published_site.py` asserts site identity, no false delivery claims, the overlay is documented and reachable, and the mark is not the old pun (issue #75) |
| 30 | A rename changes the repository; it does not change what the repository *says*. `README.md` went on calling itself "a self-improving template", promised that each project "sends what it learned back" after that flywheel was removed in #73, listed `/security` and `/reviewer` as slash commands five years of decisions ago made subagent-only, and advertised a `src/` layout deleted in #51 — while the docs site carried the same claims and neither failed a build. Prose is not checked by tests, which is exactly why it drifts: there was nothing to fail. Two consequences worth keeping separate: the *renames* (repo, slug, command) were mechanical, but the *claims* were not, and a find-and-replace could only ever have fixed the first kind. | semilla | `README.md` rewritten around the overlay, with the mount-time contract, a mounting path, the judgment layer, and a layout table that matches the repo; `tests/test_readme_copy.py` pins the specific false claims rather than a general vibe (issue #31) |
