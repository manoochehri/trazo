## Disposable installer proof

Ran the `scripts/install.sh` and source tree checked out at tag `v0.1.0` against a disposable local Git host. The fixture used the `both` adapter selection. It was not this repository. These commands reproduce the successful run from the repository root:

```sh
repo=$(pwd)
fixture=$(mktemp -d)
git clone --shared "$repo" "$fixture/source"
git -C "$fixture/source" checkout -q v0.1.0
mkdir "$fixture/host"
git -C "$fixture/host" init -q
cd "$fixture/host"
bash "$fixture/source/scripts/install.sh" install v0.1.0 --source "$fixture/source" --adapter both
cat .trazo/VERSION
wc -l .trazo/INSTALLED
find .trazo .claude -type f -print | sort
project_dir=.trazo/project
mkdir -p "$project_dir/charter"
printf 'project sentinel\n' > "$project_dir/charter/fixture-sentinel.txt"
bash "$fixture/source/scripts/install.sh" upgrade v0.1.0 --source "$fixture/source" --adapter both
test -f "$project_dir/charter/fixture-sentinel.txt"
bash "$fixture/source/scripts/install.sh" uninstall
test -f "$project_dir/charter/fixture-sentinel.txt"
```

| Operation | Observed result |
|---|---|
| Install `v0.1.0` | Passed. `.trazo/VERSION` contained `v0.1.0` and the tag commit above. The managed framework files and Claude adapter files were written. `.trazo/INSTALLED` contained 15 adapter entries. |
| Inspect installed files | Passed. The fixture contained framework files, `VERSION`, `INSTALLED`, and Claude adapter files. The `both` selection also wrote the root `AGENTS.md` and `CLAUDE.md` Trazo blocks. |
| Upgrade to `v0.1.0` | Passed. Added a fixture sentinel in `.trazo/project/charter/`; it remained after upgrade. |
| Uninstall without purge | Passed. Managed framework and adapter files and Trazo-only root blocks were removed. `.trazo/project/` and the sentinel remained. |

The successful run used a disposable shared clone, checked out at `v0.1.0`. An earlier fixture attempt used `git archive` as `--source`; the installer rejected it because an archive is not a Git repository with the requested tag. No project data was affected by that failed attempt.

This is a file inventory and installer lifecycle check, not a statistical study. Bar items A3, B1–B3, C2–C3, and D1–D3 do not apply to these claims; the independently checked path count and tag comparison are deterministic inventory operations. The initial independent skeptic verdict was **holds with caveats** ([issue comment](https://github.com/manoochehri/trazo/issues/185#issuecomment-6071711931)); at that review, the file disposition had not been decided and a fixture matching this repository's unmanifested state had not been checked. The owner later recorded the disposition. That first verdict is superseded for subsequent evidence by the updated verdict below.

## Modeled-state adoption fixture

After the owner decision, a second disposable clone was made from the stage-1 worktree at `20569d6`. It included the same unmanifested `.trazo/` and `.claude/` files, root adapters, project records, and settings as the repository at that point. The tagged install was first run without preparation: it refused the existing `.trazo/` and left the fixture clean. In the fixture only, the approved legacy framework and Claude agent/command files were removed with `git rm`; the project records and `.claude/settings.json` were retained; then `v0.1.0/scripts/install.sh install v0.1.0 --adapter both` was run from a source checkout at the tag.

Checks passed: all 26 overlay files and 14 Claude agent/command files matched the tagged sources byte-for-byte; `.trazo/VERSION` recorded `v0.1.0`; the manifest contained 14 adapter entries; all 24 project files in this later fixture were byte-identical before and after (the original 23 project paths plus this report); `.claude/settings.json` was unchanged; and text outside the Trazo marker blocks in `AGENTS.md` and `CLAUDE.md` was unchanged. The fixture staged and committed the simulated adoption, reverted that commit, and confirmed the original tracked tree was restored with a clean status. No migration command was run in the real repository.

The skeptic inspected the retained fixture and posted an updated **holds with caveats** verdict on [issue #185](https://github.com/manoochehri/trazo/issues/185#issuecomment-6071802468). Its byte comparisons and rollback checks agreed; it could not rerun the mutating fixture and did not independently verify repository checks or CI. The fixture is disposable and its assertions were run in the engineer session, so this evidence establishes the tested sequence, not an independently repeated migration. CI and repository checks are reported separately on the stage-1 PR.
